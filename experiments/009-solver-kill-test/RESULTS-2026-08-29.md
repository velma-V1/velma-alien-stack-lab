## What was demonstrated

The solver consumed only the public `TaskSpec.public_dict()` representation and used deterministic parsing, condition evaluation, graph validation/traversal, and current-locator binding.

The sealed `TaskSpec` was retained only by the harness so the existing 008 executor could score the emitted locator plan independently.

The result therefore demonstrates that, on the exact public representation used by Experiment 008, replacing neural dependency reconstruction with exact deterministic computation can recover the magnitude of capability required by the >=80% target calculation.

The 64/64 result has a 95% Wilson lower bound of approximately 94.337%, above the 93.446% solvable-cell success rate required to reach 80% over the current 2,976-cell 008 denominator if the previously identified structural ceiling remains unchanged.

## What was not demonstrated

This result does **not** establish that the same architecture can reach >=80% on natural-language, paraphrased, hidden-schema, or real-world planning tasks.

The current 008 public surface exposes a literal formal grammar:

```text
action=<ID> requires=<PREDECESSOR> condition=<CONDITION>
```

009 proves that a deterministic solver can exploit that formal structure exactly. It does not prove that a small model can infer an equivalent formal representation when the structure is implicit.

## Decision

The deterministic-solver architecture hypothesis survives the kill test and should no longer be treated as speculative for the exact 008 workload.

The next scientifically useful experiment should attack the remaining bottleneck rather than rerun 009 at larger scale:

> **representation generalization** — preserve the same underlying planning problems while removing or paraphrasing the literal dependency grammar, then measure whether a semantic compiler can construct a correct formal problem for the verified deterministic solver.

A failure there would identify semantic formalization, rather than planning/search, as the dominant remaining capability bottleneck.
